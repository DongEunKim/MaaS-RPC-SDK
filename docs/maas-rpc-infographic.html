02 — 토픽 구조
요청 (클라이언트 → 브로커)
WMT / {ThingType} / {Service} / {VIN} / {ClientId} / request 예: WMT/CGU/viss/VIN-123456/webapp-abc/request
응답 (브로커 → 클라이언트) — 단일·스트리밍 청크·EOF 공용
WMO / {ThingType} / {Service} / {VIN} / {ClientId} / response 예: WMO/CGU/viss/VIN-123456/webapp-abc/response
클라이언트 와일드카드 구독 (SDK 자동)
WMO/+/+/+/{ClientId}/response
QoS 1 · Clean Start = True · Keep-Alive 30s
서비스 와일드카드 구독
WMT/{ThingType}/{Service}/{VIN}/+/request
QoS 1 · Clean Start = True · Keep-Alive 60s
WMT — Web Mobile Terminated (클라이언트→서비스)
WMO — Web Mobile Oriented (서비스→클라이언트)
ThingType — 사물 타입 (예: CGU, SDM)
Service — 서비스 이름 (예: viss, diagnostics)
VIN — 장비 식별자 (Vehicle ID)
ClientId — 응답 라우팅용 고유 UUID

04 — MQTT 5.0 Properties 사용 규약
📌
Response Topic
요청 PUBLISH에 SDK가 자동 삽입. 서비스가 응답할 WMO 토픽을 지정.
🔗
Correlation Data
요청/응답 PUBLISH 공통. UUID v4 bytes. SDK가 pending_map / stream_map 키로 사용.
⏱️
Message Expiry Interval
요청: ceil(timeout) — stale 요청 브로커 폐기 (패턴 D). 응답: max(1, ceil(timeout−처리시간)) — stale 응답 잔류 방지.
📶
User Property: qos
"0" 또는 "1". Greengrass 브리지에서 msg.qos 신뢰 불가 문제 해결. 서버가 응답 QoS 미러링에 사용.
⌛
User Property: timeout / sent_at
timeout: 응답 Expiry 계산용. sent_at (패턴 D): Unix ms — 서버가 now−sent_at > valid_for+500ms 검증.
🆔
User Property: subscription_id
SDK 자동 발번 UUID. 패턴 C: 모든 이벤트에 포함 (QoS 0 유실 대비). stop() 호출 시 참조.
🏁
User Property: is_EOF
"true" = 마지막 응답. 패턴 A: 항상 true. 패턴 C 이벤트: false → true. 클라이언트 SDK가 단일/스트림 자동 판별.
🔌
User Property: unsubscribe_action / cancel_reason
unsubscribe_action: 패턴 C stop() 자동 참조. cancel_reason: 서버 강제 취소 시 SubscriptionCancelledError.reason.
✅
User Property: reason_code / error_detail
처리 결과 코드 (0=성공, 0x80 이상=오류). 오류 시 error_detail 상세 메시지 포함.
🏗️
Payload: action 필드
서버 SDK의 @server.action 라우팅 키. route_key 파라미터로 변경 가능 (기본값: "action").

06 — 내부 메커니즘
pending_map 단일 응답 대기 (패턴 A·B·D·E)
  1. UUID v4 → correlation_id 생성
  2. _pending[corr_id] = asyncio.Future 등록
  3. PUBLISH request_topic (Response Topic 포함)
  4. 응답 수신 → corr_id 매핑 → Future resolve
  5. timeout → Future cancel, _pending 제거
stream_map 스트리밍 (패턴 C·F 공통)
  1. _streams[corr_id] = asyncio.Queue 등록
  2. PUBLISH request_topic
  3. is_EOF=false → Queue에 StreamEvent put
  4. is_EOF=true → EOF 이벤트 put → 이터레이터 종료
  5. cancel_reason 있으면 SubscriptionCancelledError raise
SubscriptionRegistry 서버 구독 세션 관리
  1. registry.create() → (sub_id, cancel_event)
  2. 핸들러 yield 사이에서 cancel_event 자동 체크
  3. cancel_subscription(sub_id, reason) 호출 시 set()
  4. EOF 발행 시 cancel_reason User Property 첨부
